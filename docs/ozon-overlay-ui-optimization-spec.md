## 一、背景与现状（先读，避免重复踩坑）

三方定位已确认：
- **毛子 3.0.7**：重"看"，列表卡片即满屏分析面板（~26 指标），选品规则染色 + auto_favorite。
- **企鹅店长 5.2.2**：重"批处理"，导出数据表格 + 批量跟卖，无规则引擎。
- **SS ERP（本项目）**：已把两者揉进工作台，选品规则引擎 + 自主上架链路都在，UI 是最大短板。

**关键事实（防止误判）**：
- 工作台「选品」列全 `--` **不是 bug**。它是每行当场重算 `matchProductSelectionRules`；未启用任何规则时返回空数组，显示 `--` 属正常。**不要按"回写 skuStore"那套改**（`buildWorkbenchRows`/`evaluateSelectionRules`/`skuStore` 这些符号在本仓库不存在）。
- 卡片染色（`ozon-list-overlay.js:1571`）与工作台选品列（`:2822-2826`）共用同一对函数 `buildSelectionMetricRow` + `matchProductSelectionRules`，本就打通。

**当前配色/主题现状**：
- 列表主题 `SS_ERP_LIST_THEME`（`ozon-list-overlay.js:117-130`）：橙色系 primary `#ea580c` / soft `#fff7ed` / border `#fed7aa`。
- 卡片背景（`:1393`）：`linear-gradient(135deg,#fff7ed,#ffedd5)` 浅橙。
- 卡片命中染色（`:1059-1060`）：命中变蓝边 `#93c5fd` + 蓝橙渐变；未命中橙边 `#fdba74`。
- 选品规则编辑器保存按钮（`:2494`）：**蓝色 `blue #1e88e5`**——与橙色主题不统一。
- 工作台顶栏（`:2661`）：**蓝绿渐变 `#1d4ed8→#0f766e`**——与列表橙色主题割裂，是"奇怪怪"的主因之一。
- 工作台表头（`:2660`）：深灰蓝 `#293241`。

## 二、任务清单（按优先级，每条含锚点 + 验收标准）

### T1. 统一悬浮窗视觉主题（整体向毛子靠拢）—— 高优先

**问题**：列表卡片橙、工作台顶栏蓝绿、规则编辑器按钮蓝，三套配色互相打架。

**要求**：
1. 抽一份统一 token（建议扩展现有 `SS_ERP_LIST_THEME`，不要新建平行常量），补全：主色渐变、命中态色、中性灰阶、危险色。
2. 工作台顶栏（`:2661`）蓝绿渐变 → 改用主题主色渐变（暖色系），与列表卡片同源。
3. 规则编辑器保存按钮（`:2494`）蓝色 → 改主题主色。
4. 工作台表头 `#293241`（`:2660`）保留深色可接受，但需与新顶栏协调（同一冷暖倾向）。

**验收**：列表卡片、工作台、规则弹窗、编辑器四处主色出自同一 token；截图对比无明显撞色。

**注意**：所有 style 都是 JS 内联字符串拼接，改 token 后需确认所有 `${SS_ERP_LIST_THEME.xxx}` 引用点仍有效（`primary/primaryDark/primaryDarker/primarySoft/border/borderStrong/blue/surface/text/muted/headerGradient`）。

---

### T2. 命中标签渐变化（与 T3 合并处理）—— 高优先

**当前**：
- 卡片命中标签（`renderProductSelectionTags`, `:1068-1071`）：白底 + 规则色边框描边。
- 工作台选品列标签（`:2842-2845`）：同款白底描边。

**要求**：标签背景改为**基于命中规则 color 的浅色渐变**（用规则 color 派生低饱和渐变底 + 规则 color 作文字/描边），而不是固定橙色。无 color 的规则回退到主题橙。卡片与工作台两处共用同一派生函数，别写两份。

**验收**：命中标签呈规则色浅渐变；卡片 `:1068` 与工作台 `:2842` 两处渲染视觉一致。

**已确认**：与 T3 同源——标签色和卡片底色都从"命中规则的 color"派生（见截图 #4/#6 毛子规则里的 `卡片背景颜色 #e17070` 字段）。

---

### T3. 规则颜色标签功能（毛子 VIP 标签染色，截图 #2/#3）—— 中优先

**现状**：规则已有 `color` 字段（`normalizeSelectionRuleColor`, `:743`），命中时用规则色渲染标签 + 卡片染色。

**待确认需求边界**（用户原话"把他的 VIP 功能标签染色 颜色标签的功能"）：
- 毛子的行为是：命中规则的 `color` 决定卡片背景色 + 标签色（第一条命中规则的 color 作卡片底色）。
- 本项目当前：命中只切换蓝/橙两态（`:1059-1060`），**没有用规则自定义 color 染整卡背景**。

**要求（已确认要做，见截图 #4/#6 毛子规则里 `卡片背景颜色 #e17070` 字段）**：复刻毛子"用命中规则的 color 染整张卡片背景"：
1. `renderProductSelectionTags`（`:1054`）命中分支里，用 `matches[0].color` 生成低透明度背景渐变覆盖 `wrap.style.background`。
2. 保留未命中态的橙色默认。
3. 多规则命中时取 `优先级` 最高（priority 最大）那条的 color；priority 相同按数组顺序取第一条。

**验收**：配置带不同 color 的规则，命中后卡片底色随规则色变化。

---

### T4. Web 选品池页直接上架按钮 —— 中优先（A 的残余缺口）

**现状**：`apps/web/src/app/(dashboard)/selection-pool/page.tsx` 只有 刷新/导出Excel/去采集(`router.push('/collect?poolSkus=...')`)/批量移出/打开Ozon，**无上架按钮**。后端池路由仅 GET/POST/DELETE items。

**约束**：池 item（`SelectionPoolItem`）只存"引用 + 营销指标"，不含上架必需的 分类ID/type_id/属性/变体/图片集/包装尺寸。**因此不能在池页直接 publish**，必须触发 collect 拉详情再 publish。

**要求**：在池页加"批量上架"按钮，复用现有 `/collect?poolSkus=` 交接链路 + batch 页 `publishMode` + `/publish-ozon` 逻辑，减少手工跳转。**先出方案再动手**（这块改动量大、跨 web+后端，需单独规划）。

**验收**：池页选中多条 → 一键进入上架流程，无需手动跳采集页再逐个操作。

---

### T5. 详情页上架入口（毛子详情页上架样式，截图 #5/#8）—— 中优先

**现状**：详情页 `ozon-panel.js` 是**利润计算器**（成本/物流/佣金/汇率），**没有上架/加入选品池入口**。

**要求**：在详情页 panel 补"加入选品池 / 一键上架"入口，样式参照毛子详情页（截图 #5/#8）。复用工作台已有的 `publish-ozon-workbench-rows` 消息链路，不要另起后端。

**验收**：详情页可直接加入选品池 / 触发上架，走既有后端链路。

---

### T6. 企鹅店长式自动滚动 —— 中优先

**现状**：`ozon-list-overlay.js` 只有 `repositionActiveExpandedPanel`（展开面板跟随滚动，`:1542`），**没有企鹅店长那种"自动滚动列表页触发全量采集/懒加载"**。

**要求**：实现列表页自动滚动到底（触发 Ozon 懒加载，抓全所有 SKU 卡片），参照企鹅店长。需带：可启停、滚动间隔节流（防风控，配合项目既有 1-2 req/s 约束）、到底自动停止。

**验收**：点击"自动滚动"后列表自动加载完所有商品并被 overlay 识别；可随时停止。

---

### T7. 列表卡片信息密度（可选，低优先）

**结论（已调研）**：不需要把卡片做成毛子满屏面板。折叠默认 8 字段 + 「展开」34 行已接近毛子密度。

**真问题**：展开面板 `collectExpandedFields`（`:1728-1771`）是早期硬编码，后新增的对标指标（rFBS/FBP佣金、促销转化率、搜索目录浏览量/加购率、展示转化率、跟卖最高价）只进了可配置网格 `DISPLAY_FIELD_DEFS`，没同步进展开面板。

**要求**：让 `collectExpandedFields` 基于 `DISPLAY_FIELD_DEFS` 生成，消除两套清单不一致。

**验收**：用户在网格勾选的字段，展开卡片时也能看到。

---

### T8. 规则作筛选条件（超出毛子——毛子只染色，不筛选）—— 中优先

**背景**：毛子的规则只用于染色/打标（`auto_favorite` 是收藏，不是列表过滤）。用户要的是**把已配置的选品规则当筛选器用**：命中某规则的卡片/工作台行才显示，其余隐藏。这是本项目在毛子之上的增量能力，不是复刻。

**现状**：规则命中结果 (`matchProductSelectionRules` @ `:953`) 目前只驱动染色（`:1059-1060`）与标签（`:1068`），列表/工作台**没有任何按命中规则过滤的入口**。

**要求（交互细节待确认）**：
1. 在工作台顶栏（`:2661`）或规则区加一个"按规则筛选"控件——candidate：多选下拉列出已启用规则，选中后仅显示命中**任一**所选规则的行（OR 语义）；未选 = 不筛选（现状）。
2. 卡片列表同源过滤：同一筛选状态既作用于工作台行，也作用于卡片显隐，别写两套判定。
3. 过滤是纯前端视图态，**不改 skuStore、不回写、不触发重新采集**——只控制已渲染行的 display。
4. 与 T3 染色复用同一 `matchProductSelectionRules` 结果，避免每行重复算两遍（能缓存一次命中结果给染色+筛选共用最好）。

**待确认**（`需求不明先问`，动手前找用户拍板）：
- 筛选语义：命中任一所选规则(OR) 还是 全部(AND)？
- 作用域：只筛工作台，还是卡片+工作台同步？
- 是否需要"仅显示未命中任何规则"的反向筛选档？

**验收**：启用规则后可在工作台/卡片按命中规则收窄可见行；清空筛选恢复全量；不产生额外采集请求。

## 三、规则引擎正确性核对（附带项，纯校验）

写 UI 时顺手核对以下毛子字段映射是否已在本项目正确落地（`matchProductSelectionRules` @ `:953`、`buildSelectionMetricRow` @ `:1024`）：

| 规则条件 | 毛子实际读取指标 | 本项目需确认 |
|---|---|---|
| brand_option | 三态：0无品牌/1有品牌/2不限 | 是否做成布尔丢了"不限"档 |
| soldSum | soldSumCny（已换算 CNY） | 字段映射是否对齐 |
| cancelRate | nullableRedemptionRate（赎回率派生） | 已有 `deriveSelectionReturnCancelRate` ✓ |
| seller_count | follow_info.count，0/0 特判无跟卖 | 是否处理 0/0 |
| follow_min_price | follow_info=LOADING 时跳过该条件 | 是否有 LOADING 跳过 |
| 匹配语义 | 严格 AND，min/max 至少一端有值才参与 | 已是 `ruleNumberPass` AND ✓ |

**注**：`avgOrdersOnAccDays` / `avgGmvOnAccDays` 是毛子表单里的"死字段"（表单能填但匹配循环无判断块），本项目**不要**照抄进匹配引擎。

## 五、开发红线（务必遵守）

- **改前先读调用链**：所有 style 是 JS 内联字符串，改 token/结构要同步所有引用点。
- **不重复渲染逻辑**：卡片与工作台标签共用同一函数，改样式改一处即可，别 copy 两份。
- **配色统一走 token**：禁止再散落硬编码 hex，新增色值进 `SS_ERP_LIST_THEME`。
- **防风控**：T6 自动滚动、批量补数据必须节流。
- **待确认项不猜**：T8 筛选语义/作用域、T4/T5 交互细节——需求不明先问，不要臆想。（T2 色值、T3 染整卡背景已拍板，见各任务条目）
- 完成后清理：临时代码、调试 log、未用变量。
